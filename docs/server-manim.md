# サーバー Manim 改善指示書

サーバーの Manim は、式や点が時間に沿って変化する動画だけを生成する。静止画や操作可能な図は将来クライアント側で描画し、AI による画像・動画生成は使わない。

## 目的

モデルは「何を描くか」だけを出す。点の座標、文字の大きさ、画面上の位置はサーバーが決める。サーバーの Manim は動画だけを作る。

完成条件は次のとおり。

- 縦にはみ出して切れない。Manim の標準フレームは横約 14、縦 8 で、見える縦範囲はおよそ -4 から 4。今のスキーマは y を -7 から 7 まで許している。
- 日本語が表示される。数式は `MathTex` の既定フォント、ラベルは `Text` の既定（`font=""`、Pango が選ぶシステムフォント）にする。Manim は日本語フォントを同梱しない。`renderer/Dockerfile` にある `fonts-noto-cjk` を、そのシステムフォントとして使う。Noto JP を別途追加しない。
- グラフは軸と目盛りを持ち、式からサーバーがサンプリングした点を通る。モデルが書いた点列を折れ線にしない。
- 数式は重ならず、フレーム幅に収まる。
- 動画は要素を 0.5 秒ずつ `Create` するのではなく、前後の式を対応させて変形する。
- モデルが書いた Python は実行しない。

## 現状と触るファイル

今の流れは、モデルが `fluina-visual` の JSON を出し、`normalizeVisualScene` が座標を個別に -7 から 7 へ押し込み、`renderer/scene.py` がその座標へ既定サイズの `Text` と `MathTex` を置いている。グラフは `VMobject.set_points_as_corners` の折れ線で、軸がない。`MovingCameraScene` はカメラを動かしていない。

| ファイル | 変更 |

## モデルが書く JSON

言語名は `fluina-visual` のままにする。要素は最大 20、文字列は 200 文字まで。

```json
{
  "kind": "video",
  "title": "二次関数の頂点",
  "duration": 5,
  "view": { "xMin": -4, "xMax": 4 },
  "items": [
    { "type": "axes" },
    { "type": "plot", "expressions": ["x^2 - 3", "x^2 - 1", "x^2 + 1"], "color": "#4DA3FF" },
    { "type": "point", "positions": [[0, -3], [0, -1], [0, 1]], "label": "頂点" },
    { "type": "steps", "latex": ["y = x^2 - 3", "y = x^2 - 1", "y = x^2 + 1"] }
  ]
}
```

サーバーに送る `kind` は `video` のみ。`duration` は任意で、2 から 20 秒。静止画や操作可能な図はこの API から生成せず、将来のクライアント側レンダラーで扱う。

動画シーンには実際に変化するキーフレームを最低 1 つ含める。全要素が固定されたシーンは動画として受け付けない。

`view` はグラフの横範囲だけを持つ。縦範囲はサンプルからサーバーが決める。`xMin` と `xMax` は有限で、`xMin < xMax`、幅は 0.5 以上 40 以下。省略時は -5 から 5。

`items` の種類は次だけを許す。

| type | 内容 |
| --- | --- |
| `axes` | `view` の範囲で軸と目盛りを描く。グラフがあるとき、無ければサーバーが補う |
| `plot` | 固定なら `expression`、変化させるなら 2 個以上 6 個以下の `expressions` キーフレーム。色は `#RRGGBB` のみ |
| `point` | 固定なら `x` と `y`、移動させるなら 2 個以上 6 個以下の `positions`。任意の短いラベル |
| `segment` | `from` と `to`。各点は `[x, y]` |
| `circle` | `x`、`y`、`radius`。単位はデータ座標 |
| `formula` | 画面に置く数式を 1 つ。位置は書かない |
| `steps` | 動画用。`latex` の配列を 2 個以上 6 個以下。式が順に変形する |

`expressions`、`positions`、`steps` は各時点の状態を表す。連動させる配列は同じ長さにし、各時点の式・グラフ・点を対応させる。配列が短い項目は最後の状態を保つ。サーバーは隣り合う状態を同時に変形する。キーフレームの内容がすべて同じなら変化とはみなさない。

ラベルや式の `x` と `y` は禁止する。色名、`rgba`、`scale`、`animation` も禁止する。未知のキーは捨て、未知の `type` を含むシーンは描かず、今どおり「図・動画の仕様を AI が正しく出力できなかった」旨をチャットに返す。

式に使える LaTeX コマンドは今の許可リストのままにする。`\text` や `\begin` は足さない。通常の日本語は `label` や `point.label` に書く。

`expression` に使えるのは数、`x`、`pi`、`+ - * / ^`、括弧、`sqrt`、`abs`、`sin`、`cos`、`tan`、`ln`、`log`、`exp` だけ。これ以外の文字がある式は不正とする。`eval` や Python では実行しない。再帰下降などで、演算子の優先順位を保って評価する。サンプルは 161 点。非有限値の前後で線を切る。隣接点の縦の差が、有限な y の範囲の 8 倍を超えたところでも切る。`tan` の不連続を一本の線でつながないため。全部が非有限なら、その plot は描かず、シーンに描けるものが残っていれば残りだけで続ける。

データの y は -7 から 7 に押し込めない。有限なサンプルの最小と最大に 10% の余白を足して縦範囲にする。範囲が 0 なら上下に 1 を足す。絶対値が 1000 を超えるサンプルは非有限と同じ扱いにして線を切る。

## 動画への配置

`Scene` を使う。`MovingCameraScene` は使わない。描き終わったグループがフレームに収まるように、全体を一度だけ縮小する。座標を要素ごとに切らない。

フレームの内側に 0.4 の余白を取る。

- グラフがあるとき、左側約 60% を座標面にする。`Axes` の `x_range` と `y_range` はデータ範囲。点、線分、円、プロットは `axes.c2p` で置く。
- 数式と `steps` は右側、グラフが無いときは中央に、上から `buff` 0.35 で積む。各数式の幅が領域の幅を超えたら、その数式だけ縮小する。下限は元の 0.35 倍。それを下回る長さの式は、LaTeX としては描かず、失敗メッセージにする。
- `point.label` は点の上に、データ座標ではなく画面上のオフセットで置き、移動点と一緒に移動させる。`Text` にはフォント名を渡さない。幅が座標面の 40% を超えたら縮小する。既定フォントで日本語が豆腐になる場合だけ、インストール済みの `Noto Sans CJK JP` を `font` に渡す。新しいフォントパッケージは足さない。
- プロットの線幅は低解像度でも見える太さにする。点は小さいドットにする。
- タイトルはフレーム上端の余白に置く。要素の座標には使わない。
- 最後に全体のバウンディングボックスを測り、余白つきフレームより大きければ等比縮小して中央へ置く。

動画の展開とキーフレーム数はAIが問題に合わせて決める。`steps` は `TransformMatchingTex`、グラフと点は同じ時点の状態へ同時に変形する。対応できない式は `FadeOut` と `FadeIn` に落とす。キーフレーム間は 0.8 秒で変化し、待ち時間は `duration` から変形時間を引いた残りで、最低 1 秒。

サーバー動画は `-qh`（1920×1080、60 fps）で描画する。Manim のプリセットは `-ql`（854×480、15 fps）、`-qm`（1280×720、30 fps）、`-qh`（1920×1080、60 fps）、`-qp`（2560×1440、60 fps）、`-qk`（3840×2160、60 fps）。高画質ほどレンダリング時間と出力サイズが増えるため、タイムアウトを含む実運用で計測する。

## プロンプト

`askSystemInstruction` は、ユーザーが Manim 動画を明示的に求めたときだけ、上の JSON を出力するようにする。静止画だけを求められた場合や、図が説明に役立つだけの場合は JSON を出さない。`kind` は常に `video` とする。説明の展開はAIが自分で組み立て、必要なら `expressions`、`positions`、`steps` を同じキーフレーム数で連動させる。座標、`elements`、`line`、`graph`、`points`、`scale`、`animation` は書かせない。

## 正規化

`normalizeVisualScene` は、`kind: "video"` のみを受け付け、許可キー以外を落とし、色と LaTeX と expression を検証し、個数と文字数を切る。`x` や `y` を -7 から 7 へ丸める処理は削除する。丸めはグラフの形を変える。不正な plot だけを取り除き、他の item が残るならシーンは有効のままにする。

## テスト

`tests/openrouter.test.ts` の「単位円」は、新しい JSON をレンダラーへそのまま渡すことを確認する形に更新する。最低限、次を単体で足す。

- 二次関数のサンプルが頂点を通り、不連続で線が分かれること。
- y が 7 を超える点が、7 に押し潰されないこと。
- サーバーのシーンスキーマが `kind: "image"` を拒否すること。
- 変化する item のない静止シーンが拒否されること。
- 許可外の expression と、位置つきの古い要素が採用されないこと。
- グラフと点のキーフレームが正規化・検証され、動画で同期して変形すること。
- 日本語ラベルが `Text` になり、数式が `MathTex` になること。フォント名の固定は検証しない。シーン構築を Manim の描画プロセスから分離し、プロセスを起動せずに検証できるようにする。

レンダラー本体の画像比較は、この作業の必須にしない。配置関数がフレームの縦 8、横約 14 の内側に収まる矩形を返すことまでを自動テストにする。

## やらないこと

- クライアント側の静止画・操作可能な図のレンダラーは、このサーバー動画作業では実装しない。シーン JSON は後でクライアントが読める形にしておく。
- 拡散モデルや動画生成モデルへフォールバックしない。
- モデル出力の Python、Manim コード、シェルコマンドを実行しない。
- 要素の自由配置を残したまま、フォントとカメラだけ直して完了にしない。重なりと歪んだグラフは残る。
